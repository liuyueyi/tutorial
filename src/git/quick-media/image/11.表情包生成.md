# 表情包生成

> 本文介绍 `image-plugin` 中的表情包生成能力，对应的包为 `com.github.hui.quick.plugin.image.wrapper.emoticon`

在开始之前，先定一个小目标：输入一个 gif 动图（或者几张静态图），外加一句配文，输出一张可以在微信里直接斗图用的表情包，大概长下面这个样子

<!-- more -->

```
+------------------------+
|                        |
|        gif 动图        |
|                        |
|      这里是配的文字      |
|                        |
+------------------------+
```

当然，文字也可以竖排、也可以放到图片上方或者左右两侧，下面会挨个说。

### I. 场景与设计思路

> 表情包的核心，其实就一句话：**把文字和一组帧图，重新合成一个新的 gif**

微信上流行的表情包，基本都是"动态图 + 一句扎心文案"的组合。手动做一张需要打开 PS 之类的工具，而程序来做的话，流程可以完全自动化：

**输入**

- 一个 gif 动图：用 `GifDecoder` 拆成一帧一帧的 `BufferedImage`，同时记录每帧的延迟时间
- 或者一组静态图：直接当成 gif 的帧序列来用
- 一段配文：按 `\n` 分行，支持多行

**输出**

- 一张新的 gif：每一帧都是"背景文字 + 原图帧"重新绘制后的结果，再用 `GifHelper.saveGif` 合成输出

**文字布局**

表情包的文字排版，直接复用了长图文生成模块的 `ImgCreateOptions.DrawStyle` 枚举，支持三种：

- `HORIZONTAL`：横排文字，图片在上、文字在下（或者反过来，由 `imgFirst` 控制）
- `VERTICAL_LEFT`：竖排文字，从左往右排列
- `VERTICAL_RIGHT`：竖排文字，从右往左排列

**尺寸自适应**

还有一个比较贴心的设计：`build()` 的时候会执行 `calRealSize()`，根据文字的行数、字体高度、间距，自动算出画布的真实宽高。也就是说你传入的 `w`、`h` 更像一个"期望值/最小值"，最终输出的图可能会比它更大，保证文字和图片都塞得下。

### II. 依赖引入

从中央仓库直接引入最新版本即可：

```xml
<!-- https://mvnrepository.com/artifact/com.github.liuyueyi.media/image-plugin -->
<dependency>
    <groupId>com.github.liuyueyi.media</groupId>
    <artifactId>image-plugin</artifactId>
    <!-- 请使用最新版本号替换下面的版本 -->
    <version>3.1.0</version>
</dependency>
```

### III. 使用示例

> 源码里没有单独的 emoticon 测试类，下面这些姿势都是根据 `EmotionWrapper` 的实现，以及项目自带的 console 控制台里 `EmotionCreateAction` 的真实调用代码整理出来的，API 均可对上源码。

#### 1. gif 动图 + 静态文字

这是最经典的表情包玩法，对应 console 里的 `GIF_SFONT` 模板（"gif图 + 静态文字"）：

```java
@Test
public void testGifEmoticon() throws IOException {
    // 一个斗图 gif，请替换为你自己的本地文件路径
    String gif = "emotion.gif";

    EmotionWrapper.ofContent("人间不值得\n但值得吃饭")
            // 期望尺寸，最终输出可能比它大（build 时会自动扩容）
            .setW(640)
            .setH(640)
            // 四周的留白
            .setLeftPadding(20)
            .setRightPadding(20)
            .setTopPadding(20)
            .setBottomPadding(20)
            // 文字行间距
            .setLinePadding(10)
            .setFont(FontUtil.DEFAULT_FONT)
            .setFontColor(Color.BLACK)
            // 横排文字：图上文下
            .setDrawStyle(ImgCreateOptions.DrawStyle.HORIZONTAL)
            // 图片优先：图在上，文字在下；false 则文字在上
            .setImgFirst(true)
            // 载入 gif（传路径或者 InputStream 都行）
            .setGif(gif)
            .build()
            .asFile("out_gif_emoticon.gif");
}
```

说明几个点：

- `EmotionWrapper.ofContent(content)` 是文字入口，返回 `Builder`；`EmotionWrapper.ofImage(img)` 则是图片入口，先载 gif 再配文字，两个入口最终都汇到同一个 `Builder` 上，随你怎么组合
- `setGif` 有三个重载：传文件路径（内部走 `FileReadUtil.getStreamByFileName`）、传 `InputStream`、传 `List<BufferedImage>`
- 输出文件建议用 `.gif` 后缀，因为 `EmotionWrapper` 内部统一走 `GifHelper.saveGif` 保存，即便你没有传任何图片，出来的也是 gif

#### 2. 多张静态图合成表情包

对应 console 里的 `MIMG_SFONT` 模板（"多张静态图 + 静态文字"），把几张 jpg/png 串成一个动图：

```java
@Test
public void testMultiImgEmoticon() throws IOException {
    List<BufferedImage> imgs = new ArrayList<>();
    // 请替换为你自己的几张静态图
    imgs.add(ImageIO.read(new File("frame1.png")));
    imgs.add(ImageIO.read(new File("frame2.png")));
    imgs.add(ImageIO.read(new File("frame3.png")));

    EmotionWrapper.ofContent("震惊！\n他竟然又双叒叕加班了")
            .setW(400)
            .setH(400)
            .setFont(FontUtil.DEFAULT_FONT)
            .setFontColor(Color.BLACK)
            .setDrawStyle(ImgCreateOptions.DrawStyle.HORIZONTAL)
            .setImgFirst(true)
            // 直接把一组静态图当帧序列
            .setGif(imgs)
            // 不传 gif 时帧延迟默认为 0，这里手动指定每帧停留 100ms
            .setDelay(100)
            .build()
            .asFile("out_multi_emoticon.gif");
}
```

注意：传 `List<BufferedImage>` 时，帧的宽高取的是这组图里的最大宽、最大高，各帧之间的差异会以最大值为准铺画布。

#### 3. 纯文字表情包

不传任何图片，就是一张"文字表情包"，很多"文字斗图"就是这么来的：

```java
@Test
public void testTextEmoticon() throws IOException {
    EmotionWrapper.ofContent("我不管\n我最强")
            .setW(300)
            .setH(200)
            .setFontColor(Color.BLACK)
            .build()
            // 也可以不落盘，直接拿 base64，方便直接塞给前端展示
            .asString();
}
```

`asString()` 会把生成的 gif 直接编码成 base64 字符串返回，做 web 服务时可以省一次落盘。

#### 4. 竖排文字

文字竖排，图在左侧或右侧：

```java
@Test
public void testVerticalEmoticon() throws IOException {
    EmotionWrapper.ofContent("今天也是元气满满的一天")
            .setW(640)
            .setH(640)
            .setDrawStyle(ImgCreateOptions.DrawStyle.VERTICAL_LEFT) // 竖排，从左往右
            .setImgFirst(true) // 图在左，文字在右；VERTICAL_RIGHT 时相反
            .setGif("emotion.gif") // 请替换为你的 gif
            .build()
            .asFile("out_vertical_emoticon.gif");
}
```

### IV. 参数说明

`EmotionWrapper` 的所有参数都由 `EmotionOptions` 承载，通过 `EmotionWrapper.Builder` 链式设置：

| 参数 | 说明 | 备注 |
| --- | --- | --- |
| `w` / `h` | 期望的画布宽高 | 传的是"最小值"，`build()` 里的 `calRealSize()` 会按文字行数 + 图片尺寸自动扩容 |
| `content` | 文字内容 | 内部按 `\n` 分段；连续的 `\n\n` 会被规整成 `\n \n`，保证空行也占一行 |
| `font` | 文字字体 | 默认走 `FontUtil.DEFAULT_FONT`（宋体 18 号），服务器没有中文字体时记得指定，或者用 JVM 参数 `-Dquick.media.font.default=字体文件.ttf` |
| `fontColor` | 文字颜色 | 支持 `setColor(int)` 传 int 色值，内部会转 `Color` |
| `drawStyle` | 文字布局 | `HORIZONTAL` / `VERTICAL_LEFT` / `VERTICAL_RIGHT`，默认由你显式设置；也可以传字符串走 `DrawStyle.getStyle(drawStyle)` |
| `imgFirst` | 图片是否在前 | 横排时控制图上文下还是文上图下；竖排时控制图在左还是在右 |
| `leftPadding` / `rightPadding` / `topPadding` / `bottomPadding` | 四周留白 | 计算文字可用宽度和图片摆放位置时都会用到 |
| `linePadding` | 文字行/列间距 | 横排是行间距，竖排是列间距 |
| `delay` | gif 帧延迟（毫秒） | 载入 gif 时默认取所有帧延迟的最大值；传静态图列表时需要自己 `setDelay` |
| `imgs` | 帧序列 | 一般不用直接设置，`setGif` 内部完成 |

### V. 适用场景与注意点

**适用场景：**

- 批量制作表情包：给一批 gif 统一配上文案水印式的说法，一键出图
- 做成在线服务：quick-media 项目自带的 console 控制台就有对应的接口（`media/emotion/render`），支持 gif/多图两种模板上传
- 群机器人：机器人收到指令后自动合成斗图回复

**注意点：**

1. **输出一定是 gif**。整个绘制流程是"逐帧重绘 + GifHelper 合成"，所以哪怕只有文字，保存的文件也得是 gif 格式，用 `jpg` 后缀保存会得到一个打不开的文件
2. **尺寸是自动扩的**。`w`/`h` 传小了不用担心图被裁掉，`calRealSize()` 会取"内容所需尺寸"与"你传的尺寸"中更大的那个；但也别指望它能缩小——传入的 `w`/`h` 就是下限
3. **gif 的帧延迟取最大值**。载入 gif 时 `delay = max(所有帧的 delay)`，如果原 gif 各帧节奏不同，合成后节奏会被拉平；想自定义就显式 `setDelay`
4. **图片会被整体缩放**。如果 gif 原始宽高加 padding 超过画布，会等比缩放到画布内；文字区域则是按行数精确计算的
5. **无独立测试类**。image-plugin 的 test 目录下没有 emoticon 的测试，写 demo 时可以参考 console 模块 `EmotionCreateAction` 的参数组合，或者直接抄本文示例
6. **服务器环境字体问题**。Linux 服务器上没有宋体会导致中文渲染成方块，记得安装字体或通过 `-Dquick.media.font.default` 指定 ttf 文件
