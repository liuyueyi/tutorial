# 图片自动裁剪

> 本文介绍 `image-plugin` 中的图片自动裁剪能力，对应的包为 `com.github.hui.quick.plugin.image.wrapper.split`

在开始之前，先定一个小目标：手上有一张美术同学给的"素材聚合图"——一整张大图上密密麻麻摆了几十个游戏道具图标，间距随意、大小不一，我们希望程序自动把这张大图裁成一张张独立的小图。

<!-- more -->

```
大图（透明背景）：
+-------------------------------------+
|  [图标A]      [图标B]   [图标C]      |
|         [图标D]                     |
|   [图标E]         [图标F] [图标G]    |
+-------------------------------------+

裁剪后：
out/A_1.png, A_2.png, ... 每个图标一个小文件
```

这就是 `ImgSplitWrapper` 要干的事。对应 README 里写的："自动实现大资源图，裁剪为一个一个的小图"。

### I. 场景与设计思路

> 关键词：**不按网格切，按内容切**

传统的雪碧图切割工具，要求素材是等间距等尺寸的网格排列，切法就是固定行列。但现实中的聚合图往往是美术随手摆的，间距不均匀，甚至图标大小都不一样，网格切法直接歇菜。

`image-plugin` 的思路是：

1. **背景判定**：传入一个 `Predicate<Integer>`（入参是像素的 int 颜色值，返回 true 表示这是背景色），默认判定是"透明像素即背景"。这一步把图片分成"内容"和"背景"两类点
2. **找边界点**：从左上角开始逐行扫描，找到第一个不是背景的点
3. **边框扫描**：以这个点为起点，沿着上/下/左/右/四个斜角共 8 个方向扩散，凡是"自身不是背景点、且 8 邻域里有背景点"的点都算边界点，一路记录上下左右四个极值，直到扫不出新点为止——这一圈下来，就得到了这个图案的外接矩形
4. **裁剪 + 抹除**：按外接矩形把这块区域拷贝成一张新图；同时把原图上这块区域全部置为透明，防止下一轮又扫到它
5. **循环**：回到第 2 步继续找下一个图案，直到整张图全是背景色

所以它裁出来的不是"格子"，而是"图案"——每个图案一张图，天然不重叠，也不依赖排列规律。

### III. 使用示例

> 以下代码取自源码测试类 [ImgSplitTest.java](https://github.com/liuyueyi/quick-media/blob/master/plugins/image-plugin/src/test/java/com/github/hui/quick/plugin/test/feat/split/ImgSplitTest.java)

#### 1. 透明背景的素材大图（默认背景判定）

最省事的姿势，什么都不用配，透明色自动当背景：

```java
@Test
public void split() throws IOException {
    try {
        // 一张透明背景的素材聚合图，请替换为你自己的文件
        String img = "D:\\quick-media\\resource\\assets\\bundle_item_icon\\img\\2766150e-9c1a-4025-b652-5b0d6b7b3fa9.e792b.png";
        ImgSplitWrapper.build().setImg(img)
                // 裁剪后保存图片的路径
                .setOutputPath("d:/quick-media/items/e792b")
                // 裁剪后图片名前缀
                .setOutputImgName("e792b")
                // 输出文件名为 前缀_序号.png，这个参数控制起始序号，默认从 0 开始
                .setOutputIncrIndex(1)
                .build()
                .splitAndSave();
        System.out.println("over");
    } catch (Exception e) {
        e.printStackTrace();
    }
}
```

输出结果就是 `d:/quick-media/items/e792b/e792b_1.png`、`e792b_2.png`……每个图案一个文件。

#### 2. 白底大图（自定义背景判定）

如果不透明背景（比如白色），默认判定就失效了，需要自己给 `bgPredicate`：

```java
@Test
public void split2() throws IOException {
    try {
        String img = "http://cdn.hhui.top/git/quick-media/futu.jpg";
        ImgSplitWrapper.build().setImg(img)
                // 裁剪后保存图片的路径
                .setOutputPath("d:/quick-media/")
                // 裁剪后图片名
                .setOutputImgName("tu")
                // 上面这个图会裁剪成4个图，生成的图片分别为 tu_1, tu_2, tu_3 等，下面这个参数则控制的是文件名中的序号
//                    .setOutputIncrIndex(1)
                // 用于指定图片中哪些颜色为背景色
                .setBgPredicate(new Predicate<Integer>() {
                    @Override
                    public boolean test(Integer rgb) {
                        Color color = new Color(rgb, true);
                        // 透明的地方当作背景，白色系认为是背景
                        return color.getAlpha() <= 10 || color.getRed() >= 220 && color.getGreen() >= 220 && color.getBlue() >= 220;
                    }
                })
                .build()
                .splitAndSave();
        System.out.println("over");
    } catch (Exception e) {
        e.printStackTrace();
    }
}
```

这个判定式的意思是：alpha 小于等于 10 的（透明）算背景；R/G/B 都大于等于 220 的（接近白色的浅色）也算背景。阈值可以根据素材的实际情况调，比如边缘有抗锯齿的浅灰色过渡带，就把阈值放宽一点。

#### 3. 批量处理一个目录

真实项目里往往是一批聚合图要处理，测试类里就是这么干的：

```java
@Test
public void testSplit() throws IOException {
    String path = "D:\\quick-media\\resource\\assets\\bundle_item_icon\\img";
    File file = new File(path);
    int i = 1;
    for (File f : file.listFiles()) {
        if (f.getName().endsWith("png")) {
            String name = f.getAbsolutePath();
            String out = name.substring(name.indexOf(".") + 1, name.lastIndexOf("."));

            try {
                ImgSplitWrapper.build().setImg(name)
                        .setOutputPath("d:/quick-media/items/" + out)
                        .setOutputImgName(out)
                        .setOutputIncrIndex(1)
                        .build()
                        .splitAndSave();
            } catch (Exception e) {
                e.printStackTrace();
            }
        }
    }
}
```

#### 4. 不落盘，直接拿裁剪结果

如果后续还想自己加工（加水印、改尺寸、上传 OSS 之类），用 `split2imgs()` 拿内存中的 `List<BufferedImage>` 即可，不会写任何文件：

```java
List<BufferedImage> imgs = ImgSplitWrapper.build().setImg("tu.png") // 请替换
        .build()
        .split2imgs();
```

### IV. 参数说明

`ImgSplitWrapper` 的所有参数由 `ImgSplitOptions` 承载：

| 参数 | 说明 | 默认值 |
| --- | --- | --- |
| `img` | 原图，支持路径（本地/http 均可）或 `BufferedImage` | 必传 |
| `outputPath` | 裁剪结果保存目录，目录不存在会自动创建 | `/tmp` |
| `outputName` | 输出文件名前缀 | 随机 UUID |
| `outputIncrIndex` | 输出文件名的起始序号，文件名为 `前缀_序号.png` | `0` |
| `bgPredicate` | 背景色判定，入参为像素 int 颜色值，返回 true 表示是背景 | alpha == 0（透明即背景） |

两个出口方法：

| 方法 | 行为 |
| --- | --- |
| `splitAndSave()` | 裁剪并按上面的规则落盘，固定输出 png 格式 |
| `split2imgs()` | 只裁剪，结果留在内存里，自己爱怎么处理怎么处理 |

### V. 适用场景与注意点

**适用场景：**

- 游戏素材加工：美术给的道具/装备聚合图，一键拆成单件素材
- 图标集拆分：设计稿里一堆零散 icon，需要拆出来入库
- 截图整理：把一张截图里的多个 UI 元素抠成独立小图

**注意点：**

1. **背景判定是整个功能的核心**。`bgPredicate` 配得不准，要么整图被当成一个图案（背景没圈住），要么图案被切碎（图案内部的浅色区域被误判为背景）。判定条件建议"宁紧勿松"，先在测试图上跑 `split2imgs()` 看看结果再调阈值
2. **连在一起的图案分不开**。边框扫描是按连通边界走的，两个图案如果在像素上紧挨着（8 邻域连通），会被当成一个整体裁出来。要求拆分的话，素材之间至少要留一像素的背景带
3. **输出的外接矩形可能是空的**。如果某个"图案"其实宽高为 0（比如一个孤立的背景判定歧义点），会自动跳过，不会产出 0×0 的文件
4. **落盘固定是 png**。`splitAndSave()` 内部写死了 `ImageIO.write(bi, "png", ...)`，透明通道不会丢；jpg 源图裁出来也建议存 png
5. **性能与图的大小成正比**。每拆一个图案都要重新扫一遍全图找起点，大图（比如 4K 素材图）会比较慢，属于一次性加工场景，跑批不用太在意，别放进实时接口就好
6. **默认输出路径是 `/tmp`**。Windows 下这个路径不一定存在，用 `splitAndSave()` 前记得显式 `setOutputPath`，免得文件写到意想不到的地方
