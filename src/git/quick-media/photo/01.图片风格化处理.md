# 图片风格化处理

> 把一张照片变成手绘素描，或者变成一张可以涂色的线稿，这类"换画风"的需求在 Java 里怎么做？本文介绍 QuickMedia 中的 photo-plugin：纯 Java 实现、不依赖任何外部环境，一行链式调用即可完成图片的风格化处理。

<!-- more -->

## I. 问题背景

图片风格化，指的是不改变图片内容本身，而是改变它的"画风"，典型场景有：

- 把照片转成**素描画**，用于生成手绘风格的头像、海报素材
- 把照片转成**线稿（轮廓线）**，用于涂色本、漫画分镜、图片轮廓提取

这些效果的底层都是一些经典的图像处理算法：灰度化、卷积、高斯模糊、颜色混合。原生 JDK 的 `BufferedImage` 逐像素操作完全能实现，但每次都手写一遍太痛苦了；而像 ImageMagick 这种外部工具虽然功能强大，却需要在服务器上装环境，对于只是想"加个滤镜"的场景来说太重了。

photo-plugin 选择了中间路线：**纯 Java 实现**（基于 BufferedImage 逐像素运算，辅以 jhlabs 图像处理库），零环境依赖，引入 jar 即可使用。它把每种风格封装成一个"算子"（Operator），对外暴露统一的链式 API，用起来和 QuickMedia 其他插件保持了同一套手感。

## II. 依赖引入

在 pom.xml 中添加依赖，请注意使用最新的版本：

```xml
<dependency>
    <groupId>com.github.liuyueyi.media</groupId>
    <artifactId>photo-plugin</artifactId>
    <version>3.1.0</version>
</dependency>
```

photo-plugin 内部依赖了 base-plugin 和 `com.github.liuyueyi:java-jhlabs`（灰度、反色、高斯模糊、混合模式这些基础滤镜的来源），这些会作为传递依赖自动引入，不需要手动添加。

## III. 使用姿势总览

photo-plugin 的入口是 `PhotoOperateWrapper`，所有算子共用同一套使用姿势：

```java
BufferedImage out = PhotoOperateWrapper.of(OperatorEnum.SKETCH)
        .setImg("https://t7.baidu.com/it/u=4162611394,4275913936&fm=193&f=GIF")
        .build()
        .asImg();
```

拆解一下这个链式调用：

- `PhotoOperateWrapper.of(OperatorEnum)`：指定算子，当前支持 `SKETCH`（素描）和 `EDGE`（边缘检测）两种，返回对应的配置对象
- `setImg(...)`：指定输入图片，支持 `String` 路径（网络地址 / 本地绝对路径 / `~/` 用户目录 / classpath 相对路径）和 `BufferedImage` 对象
- 中间的 `setXxx(...)`：算子各自的参数配置，链式叠加
- `build()`：配置完成，返回 `PhotoOperateWrapper` 对象（这一步可以省略，直接接输出方法）
- `asImg()` / `asFile(fileName)`：输出结果，前者返回 `BufferedImage`，后者直接保存文件

```java
// 保存到文件
PhotoOperateWrapper.of(OperatorEnum.SKETCH)
        .setImg("sketch_in.jpg")
        .build()
        .asFile("d://quickmedia/sketch_out.png");
```

`asFile` 内部会自动创建父目录，保存的图片格式由 `setImgType` 决定（默认 `png`）。

## IV. 素描算子：SKETCH

### 1. 基本使用

```java
@Test
public void testSketch() {
    BufferedImage out = PhotoOperateWrapper.of(OperatorEnum.SKETCH)
            .setImg("https://t7.baidu.com/it/u=4162611394,4275913936&fm=193&f=GIF")
            .build()
            .asImg();
    System.out.println("----");
}
```

<!-- 效果图待补充：testSketch 输出的素描效果图（原图与素描效果对比） -->

### 2. 效果说明

不设置任何参数，得到的就是一张标准的手绘素描效果：主体轮廓以深色铅笔线条呈现，原图中的大块色彩被"抹掉"，只留下明暗和纹理。

### 3. 参数调节

素描算子提供了两个可调参数：

| 参数 | 类型 | 默认值 | 说明 |
| :-: | :-: | :-: | --- |
| `radius` | float | 20f | 高斯模糊半径，控制笔触的柔和程度。值越大，模糊越厉害，素描线条越柔和；值越小，保留的原图细节越多，线条越"锐利" |
| `alpha` | float | 1.0f | 颜色减淡混合的强度，影响画面的明暗对比 |

```java
// 笔触更柔和的素描
BufferedImage out = PhotoOperateWrapper.of(OperatorEnum.SKETCH)
        .setImg("in.jpg")
        .setRadius(40f)
        .setAlpha(1.0f)
        .build()
        .asImg();
```

### 4. 实现原理

素描的算法流程是经典的"颜色减淡"（Color Dodge）玩法，一共四步：

1. **灰度化**：用 `GrayscaleFilter` 把彩色图变成灰度图，这一步去掉了所有颜色信息，只保留明暗
2. **反色**：用 `InvertFilter` 对灰度图做反色（黑变白、白变黑）
3. **高斯模糊**：对反色后的图做高斯模糊（半径即 `radius` 参数），让边缘发散
4. **颜色减淡混合**：将模糊后的反色图与原始灰度图做 ColorDodge 混合（混合强度即 `alpha` 参数）

ColorDodge 混合的直观理解是：结果 = 底图 / (1 - 顶图)。反色图模糊之后，原图的轮廓处颜色深、平坦区颜色浅，两者相除之后，平坦区域会被"提亮"到接近白色，而轮廓区域保持深色——于是画面上就只剩下了深色的轮廓线条，这正是素描的视觉效果。这套流程在网上被称为"PS 素描滤镜"的算法版，很多语言都有等价实现。

## V. 边缘检测算子：EDGE

### 1. 基本使用

边缘检测算子的配置项比素描多，先看一个使用 `parse` 方式的完整示例（官方测试 case）：

```java
@Test
public void testSobel() {
    BufferedImage out = PhotoOperateWrapper.of(OperatorEnum.EDGE)
            .parse(EdgeOperator.EdgeOperateOptions.type())  // 拿到 EDGE 算子的专属配置
            .setType(EdgeOperator.EdgeType.SOBEL)           // 指定边缘检测算法
            .setBgColor(Color.WHITE)                        // 背景色：白
            .setLineColor(Color.BLACK)                      // 线条色：黑
            .setImg("https://img2.woyaogexing.com/2017/05/24/432c24863a7ab65a!600x600.jpg")
            .build()
            .asImg();
    System.out.println("----");
}
```

这里有个使用上的小细节值得说明：`PhotoOperateWrapper.of(OperatorEnum.EDGE)` 返回的声明类型是通用的 `OperateOptions`，而 `setType`、`setThreshold` 这些是 EDGE 算子专属的配置方法。要调用它们，有两种姿势：

```java
// 姿势一：parse 方式，通过 EdgeOperateOptions.type() 把配置对象"还原"为专属类型
PhotoOperateWrapper.of(OperatorEnum.EDGE)
        .parse(EdgeOperator.EdgeOperateOptions.type())
        .setType(EdgeOperator.EdgeType.SOBEL)
        ...

// 姿势二：强转
((EdgeOperator.EdgeOperateOptions<PhotoOperateWrapper>) PhotoOperateWrapper.of(OperatorEnum.EDGE))
        .setType(EdgeOperator.EdgeType.CANNY)
        ...
```

两种写法效果等价，`parse` 的写法链式调用更顺滑一些。

### 2. 内置的六种算法

边缘检测通过 `EdgeType` 枚举切换，一共内置六种算法：

| EdgeType | 卷积核尺寸 | 默认阈值 | 特点 |
| :-: | :-: | :-: | --- |
| `SOBEL`（默认） | 3x3 | 200 | 最常用的梯度算子，对水平/垂直边缘响应好，抗噪能力中等 |
| `PREWITT` | 3x3 | 200 | 与 Sobel 类似的简化版，权重均匀，效果略平一些 |
| `KIRSCH` | 3x3 | 200 | 八方向卷积取最大值，对斜向边缘更敏感 |
| `LAPLACIAN` | 3x3 | 50 | 二阶导数算子，对细节和噪声都很敏感，线条更碎 |
| `ROBERTS` | 2x2 | 50 | 最小的 2x2 算子，计算快，但抗噪能力弱 |
| `CANNY` | - | - | 完整的多阶段边缘检测算法，线条连续性最好，推荐 |

默认阈值因算法而异（梯度量级不同），实际使用时按图片效果微调即可。

### 3. 参数说明

`EdgeOperateOptions` 提供四个配置项：

| 参数 | 默认值 | 说明 |
| :-: | :-: | --- |
| `type` | `SOBEL` | 边缘检测算法 |
| `threshold` | 各算法自带默认值 | 边缘判定阈值：梯度值大于阈值的像素判为边缘（画线条色），否则判为背景（画背景色）。**阈值越小，保留的边缘越多，画面越"密"；越大则只剩最显著的轮廓** |
| `bgColor` | 黑 | 背景色，支持 `Color` 对象或 int 色值 |
| `lineColor` | 白 | 线条颜色 |

也就是说，默认输出是"黑底白线"，想得到常见的"白底黑线"涂色本线稿，把两个颜色对调即可。

```java
// 白底黑线的 Canny 线稿（官方测试 case）
@Test
public void testCanny() {
    BufferedImage out = ((EdgeOperator.EdgeOperateOptions<PhotoOperateWrapper>) PhotoOperateWrapper.of(OperatorEnum.EDGE))
            .setType(EdgeOperator.EdgeType.CANNY)
            .setBgColor(Color.WHITE)
            .setLineColor(Color.BLACK)
            .setImg("https://img0.baidu.com/it/u=591720380,976271434&fm=253&fmt=auto&app=138&f=JPEG?w=500&h=1111")
            .build()
            .asImg();
    System.out.println("----");
}
```

### 4. 各算法的效果差异与选择建议

同样是白底黑线的配置，不同算法输出的线稿风格差异挺明显：

- **SOBEL / PREWITT**：线条粗细均匀，主要是横竖两个方向的轮廓，适合快速出"简笔画"风格的线稿
- **KIRSCH**：八方向扫描，斜向线条（如头发丝、树叶边缘）保留得更全，但画面也会显得更密
- **LAPLACIAN**：二阶导数，对细微纹理敏感，出来的线条比较碎，适合纹理提取而不是整图线稿
- **ROBERTS**：计算量最小，效果也最"糙"，适合对性能敏感、对效果要求不高的场景
- **CANNY**：线条最连续、最干净，几乎只有真正的物体轮廓，做涂色线稿首选

一个实用提示：除 CANNY 外的几种算法在实现上是逐像素 `getRGB`/`setRGB` 的方式做卷积，**大图处理会比较慢**，使用前建议先把图片压缩到合适的尺寸（可以配合 imagic-plugin 的 `scale` 先做一步缩放）；Canny 内部使用整型数组一次性处理，相对高效一些。

## VI. Canny 边缘检测原理简述

Canny 是边缘检测领域的经典算法（1986 年由 John Canny 提出），photo-plugin 在 `com.github.hui.quick.plugin.photo.util.CannyFilter` 中做了完整的纯 Java 移植（实现思路参考：[Canny 边缘检测的 Java 实现](https://blog.csdn.net/yeweij226/article/details/99747631)）。整个流程分五步：

1. **灰度化**：把彩色图按 `0.299R + 0.587G + 0.114B` 的亮度公式转成灰度图，边缘检测只关心亮度突变，不关心颜色
2. **高斯平滑**：用高斯核对图片做平滑滤波，抹掉细小的噪声点。这一步很关键——不做平滑的话，噪声会被当成"边缘"检测出来。平滑力度由 `gaussianKernelRadius` 控制
3. **计算梯度**：对平滑后的图计算每个像素的梯度幅值和方向（亮度变化最剧烈的地方就是边缘的候选位置）
4. **非极大值抑制**（Non-Maximum Suppression）：边缘候选点沿梯度方向只保留幅值最大的那个点，把"粗边"细化成一条像素宽的细线，同时排除不是局部最大的伪边缘
5. **双阈值 + 滞后连接**（Hysteresis）：设定高、低两个阈值（即 `highThreshold` 和 `lowThreshold`）。梯度高于高阈值的一定为边缘；低于低阈值的一定不是；介于两者之间的像素，只有当它与已确定的边缘连通时才算边缘。这一步把断裂的弱边缘"接"回强边缘，让线条保持连续

CannyFilter 对外暴露了几个可调参数（低阈值、高阈值、高斯核半径等），不过在 EDGE 算子中调用时，内部固定使用了 `lowThreshold = 0.5f`、`highThreshold = 1.5f` 的经验值，通常不需要干预。如果想体验参数调节，也可以直接拿 `CannyFilter` 来用：

```java
CannyFilter detector = new CannyFilter();
detector.setLowThreshold(0.5f);
detector.setHighThreshold(1.5f);
detector.setSourceImage(img);
detector.process();
BufferedImage edges = detector.getEdgesImage();
```

## VII. 小结

本文介绍了 photo-plugin 的完整用法：

- **SKETCH 素描**：灰度 → 反色 → 高斯模糊 → ColorDodge 混合，`radius` 控制笔触柔度，`alpha` 控制对比强度
- **EDGE 边缘检测**：六种算法（SOBEL / PREWITT / KIRSCH / LAPLACIAN / ROBERTS / CANNY）可切换，线条色、背景色、阈值均可定制，CANNY 效果最好，是线稿场景的首选

整个插件纯 Java 实现，零外部环境依赖，配合 QuickMedia 的 image-plugin（图片合成）和 imagic-plugin（基于 ImageMagick 的图片编辑），基本可以覆盖"图片加工"的大部分场景。
